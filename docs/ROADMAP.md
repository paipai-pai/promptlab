# PromptLab 路线图

## 总体原则

Phase 按依赖顺序推进，每一阶段通过验收后再进入下一阶段。未确认的产品问题先记录，不以隐含默认值扩大范围。

## Phase 0：工程初始化与规范

状态：已完成。

目标：建立可维护、可验证的工程基线。

交付：Next.js App Router、严格 TypeScript、Tailwind、ESLint、shadcn/ui、Supabase/Zod/Vitest 依赖、基础目录、示例环境变量、最小首页及项目文档。

验收：lint、类型检查、单元测试、生产构建通过，开发服务器可启动并返回首页。

## Phase 1：静态 UI 与交互原型

状态：已完成。

依赖：Phase 0。

目标：在无后端数据的情况下确认工作台信息架构和关键交互。

建议交付：

- 应用壳层、响应式主导航、明暗主题切换
- Prompt 列表空态与示例态
- Prompt 编辑页静态布局
- 变量输入与预览的本地演示
- 版本历史与实验表单的静态状态
- 关键加载、错误、空态和未保存草稿提示

限制：使用静态 fixture；不连接数据库，不伪装真实保存成功。

验收：PRD 核心对象均有可评审界面；桌面与移动布局可用；键盘焦点和基础可访问性通过检查。

## Phase 2：认证、数据库与安全基线

状态：已完成（P2-01 至 P2-04，2026-10-20）。

依赖：Phase 1 已确认信息架构；评分、删除、变量命名规则至少完成必要决策。

目标：建立 Supabase 本地开发、认证、私有数据模型和真实 Prompt CRUD，并完成集成与安全验收。

实际交付：

- P2-01：Supabase SSR 客户端、邮箱注册/确认、登录/退出、Cookie 会话刷新和私有路由保护
- P2-02：三张业务表、约束/索引/RLS、Prompt + v1 原子函数、pgTAP 权限测试和生成的数据库类型
- P2-03：真实 Prompt 列表、搜索、分类、分页、创建、元数据更新、删除与工作台数据接入
- P2-04：普通用户 A/B 安全矩阵、Playwright Chromium 核心流程、异常与 Phase 1 UI 回归

验收：匿名、所有者、其他用户的访问矩阵通过；创建只生成一个 v1；刷新可读取；元数据更新不新增版本；删除级联；ESLint、类型检查、Vitest、pgTAP、Playwright 和生产构建通过。

## Phase 3：不可变版本历史

依赖：Phase 2。

目标：在当前草稿编辑器上完成 v2/v3 正式版本追加和历史查看。

建议交付：显式保存新版本、并发安全版本号、只读历史、版本详情，以及以历史版本内容创建新版本的受控恢复流程。

验收：任何应用路径均不能覆盖或删除历史正文；并发保存不产生重复版本号；恢复不修改旧版本，而是追加新版本；草稿仍不能关联正式实验。

## Phase 4：手动实验记录

依赖：Phase 3。

目标：让人工实验与具体已保存版本建立稳定关联。

交付：从已保存版本创建实验，记录输入快照、模型名称、输出、评分和备注，并提供实验列表与详情。

验收：实验始终指向保存时的版本；输入快照不会被后续编辑改变；跨用户访问被阻止。

## Phase 5：持续评价与迭代

依赖：Phase 4；评分与模型名称规则已确认。

目标：围绕已保存版本和手动实验形成可追溯的评价与迭代闭环。

范围待确认：在进入本阶段前明确聚合视图、比较维度和评价工作流；MVP 不接入模型 API，也不自动优化 Prompt。

验收：待产品范围确认后补充，不以隐含默认扩大功能。

## Phase 6：质量加固与发布准备

依赖：Phase 5。

目标：完成真实上线前的端到端验证和运维准备。

交付：扩展现有 Playwright 回归至版本与实验流程，并完成可访问性、性能、部署/迁移/回滚清单和日志隐私检查。

验收：核心用户路径端到端通过；生产构建通过；部署与回滚步骤经过演练；无真实密钥进入仓库或客户端包。

## 关键依赖链

```text
Phase 0 → Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5 → Phase 6
```

版本历史依赖已通过验收的数据模型、RLS、原子操作和 Prompt 编辑流程；正式实验依赖已保存版本；现有 E2E 在后续阶段随业务流程扩展。
